# 剪映时间线

## 输入与剪切

提供最终旁白、与它匹配的 UTF-8 SRT、通过画面质检的 MP4、草稿名和输出目录。用户提供单条已有的旁白且需要对齐时，用已有的带时码转录，或在支持语音识别的剪映里导出对应 SRT 后运行。由真实时码决定剪切点。

`cuts.json` 用 `through_cue` 指定每个镜头覆盖到第几条字幕，按 SRT 中出现的顺序从 1 开始编号。条目依次递增，最后一个覆盖字幕总条数。路径相对于 `cuts.json`，也可用绝对路径。

```json
[
  {"clip": "shots/01/omni-v01/clip.mp4", "through_cue": 1},
  {"clip": "shots/02/omni-v01/clip.mp4", "through_cue": 3, "in_ms": 0, "out_ms": 4800}
]
```

默认使用整个原片。若源片开头或结尾含多余画面，用 `in_ms`、`out_ms` 保留所需范围。画面从 0 开始并铺满旁白。相邻两镜在下一镜第一条字幕的开头切换。剪映以可编辑的速度参数把选用的源片时长适配到目标区间。语音保持原时长。若画面速度明显偏快或偏慢，重新分配句子或选更合适的镜头段长。

```bash
python3 "$SKILL/scripts/draft.py" \
  --audio voice/narration.wav --srt voice/subtitles.srt --cuts cuts.json \
  --root jianying-drafts --name '纸片短片 v01'
```

草稿包括画面轨、旁白轨和可编辑中文字幕轨，导入的源片声音置为静音。字幕默认为底部居中白字和描边。脚本输出实际时长、轨道片段数与每镜速度，检查字幕超过片尾、时码重叠和素材引用失败等情况。同名新版本需另取名称。

## 在剪映打开

在剪映专业版设置中查看当前草稿位置。可在生成时由 `--root` 指定该路径，让草稿元数据从一开始就指向正式位置。仅需交付时，可把整个草稿目录连同视频、旁白和 SRT 路径清单交给用户。草稿里的素材引用是本机绝对路径，移动项目素材后需要在剪映重新定位。当剪映首页未刷新时，返回草稿列表或重启专业版后再查找。打开后检查声音、素材链接、字幕和裁切，微调后在剪映中导出。

脚本写入 pyJianYingDraft 的明文草稿，包括 `draft_content.json`、`draft_info.json` 和 `draft_meta_info.json`。客户端版本会影响明文草稿的读取。对当前版本是否可打开，以上机实测为准。

当前客户端未识别明文草稿时，若有可用的桌面操作工具，可在剪映中直接新建草稿。导入各镜 MP4、合并旁白和 SRT。旁白从 0 开始，视频按 `cuts.json` 顺序排放并用下一镜的字幕起点定裁切和速度，SRT 从 0 导入独立字幕轨。以实际界面为准，在时间线上核对三轨和片尾长度。若当前会话无法操作剪映，交付原 MP4、旁白、SRT 与镜头表供打开后接续。
